# Развёртывание HomeEdu на Beget

**Текущее состояние на 12 сентября 2026 года:** технический сайт и MySQL созданы, release загружался, однако развёртывание не принято из-за ответа 403 после обновления. До успешной проверки `/api/v1/health` и полного пользовательского сценария production считается неработающим.

Эта инструкция предназначена для обычного виртуального хостинга Beget. Node.js на сервере не нужен: frontend собирается локально или в CI, а в production работают Apache, PHP и MySQL.

## 1. Требования

- домен или технический домен, добавленный в разделе «Сайты»;
- PHP 8.2 или новее с `pdo_mysql`, `mbstring` и `fileinfo`;
- MySQL 8, если эта версия доступна на выбранном сервере;
- сертификат Let’s Encrypt для собственного домена; для первого запуска на техническом домене он не требуется;
- SSH-доступ для миграций и резервного копирования.

Доступные версии PHP и MySQL зависят от сервера аккаунта — проверьте их в панели Beget. Для базы используйте `utf8mb4`.

## 2. Сборка релиза

```bash
npm ci
npm run test:quality
npm run build:beget
```

Команда создаёт:

- `release/homeedu-beget/public_html` — только статический frontend и публичная точка API;
- `release/homeedu-beget/private/api` — PHP-код, миграции и шаблон конфигурации;
- `release/homeedu-beget/private/uploads` — закрытое хранилище работ;
- `release/homeedu-beget.tar.gz` — готовый архив для загрузки.

Настоящий `.env`, пользовательские файлы и резервные копии в архив не входят.

## 3. Настройка Beget

1. Создайте сайт и привяжите домен. Рабочая директория домена должна оканчиваться на `public_html`.
2. Выберите PHP 8.2 или новее для домена.
3. Создайте базу MySQL. На виртуальном хостинге Beget имя пользователя обычно совпадает с именем базы.
4. Для первого запуска на техническом домене оставьте HTTP без принудительного перенаправления. После подключения собственного домена выпустите Let’s Encrypt, проверьте HTTPS и только затем включите перенаправление в панели Beget. Базовый релиз намеренно не содержит HTTPS rewrite и HSTS, чтобы сайт не становился недоступным до выпуска сертификата.
5. Загрузите содержимое каталогов `public_html` и `private` из архива в корень сайта, сохранив их соседнее расположение:

```text
site-root/
├── public_html/
│   ├── index.html
│   ├── assets/
│   ├── .htaccess
│   └── api/
└── private/
    ├── api/
    └── uploads/
```

Не помещайте `private`, `.env` или загруженные детьми файлы внутрь `public_html`.

## 4. Production-конфигурация

В SSH-консоли скопируйте шаблон и ограничьте права:

```bash
cd ~/ИМЯ_САЙТА
cp private/api/.env.production.example private/api/.env
chmod 600 private/api/.env
chmod 700 private/uploads
pwd
```

Заполните `private/api/.env` реальными значениями. Для `UPLOADS_PATH` используйте абсолютный путь, полученный из `pwd`, например `/home/LOGIN/ИМЯ_САЙТА/private/uploads`. Сгенерируйте setup token локально:

```bash
openssl rand -hex 32
```

Обязательные правила:

- `APP_ENV=production`;
- `APP_URL` начинается с `https://`;
- `APP_SETUP_TOKEN` и пароль MySQL уникальны и не попадают в Git;
- `AI_API_KEY` остаётся пустым, пока AI-провайдер не подключён осознанно;
- frontend и API работают на одном домене, поэтому CORS не требуется.

## 5. Миграции и первый запуск

Из корня сайта выполните миграции интерпретатором выбранной версии PHP:

```bash
php8.2 private/api/bin/migrate.php
```

Если такой команды нет, возьмите путь к CLI-интерпретатору в информации о сервере Beget. Затем проверьте:

```bash
curl -fsS https://ВАШ_ДОМЕН/api/v1/health
```

Откройте `https://ВАШ_ДОМЕН/setup`, один раз создайте семейное пространство и после этого войдите как родитель.

## 6. Обновление и откат

Перед каждым обновлением:

1. создайте резервную копию MySQL и каталога `private/uploads`;
2. сохраните предыдущий release-каталог;
3. загрузите новый frontend и PHP-код, не перезаписывая `.env` и `uploads`;
4. примените миграции;
5. проверьте health, вход родителя, вход ученика, открытие урока и отправку работы.

При ошибке верните предыдущие `public_html` и `private/api`, оставив production `.env` и `private/uploads`. Откат базы выполняйте только из проверенной резервной копии, если новая миграция уже изменила данные.

## 7. Эксплуатационные ограничения

- не запускайте локальные AI-модели и постоянные фоновые процессы;
- не загружайте видео — используйте ссылки или встраивание;
- следите за квотой диска и размером `private/uploads`;
- настройте регулярное резервное копирование;
- при появлении нескольких семей, очередей или высокой AI-нагрузки перенесите API и БД на VPS.

## 8. Диагностика ответа 403 после загрузки

1. В панели Beget убедитесь, что технический домен привязан к каталогу конкретного сайта, а document root оканчивается на `public_html`.
2. Проверьте наличие читаемого `public_html/index.html` и отсутствие ошибочной вложенности `public_html/public_html`.
3. Для каталогов используйте права не строже `755`, для публичных файлов — `644`; не открывайте доступ к `.env` и `private/uploads`.
4. Временно проверьте минимальный статический файл без PHP. Если он тоже возвращает 403, причина находится в привязке сайта, правах или конфигурации хостинга, а не в React/API.
5. Откройте access/error logs в панели Beget и зафиксируйте точную причину до очередной перезагрузки файлов.
6. После восстановления статики проверьте `/api/v1/health`, затем вход и учебный цикл. Не удаляйте рабочую базу, `.env` и `private/uploads` при повторной загрузке release.
