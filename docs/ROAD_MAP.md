# HomeEdu — Road Map

**Версия:** 1.0  
**Репозиторий:** `https://github.com/KebogdBP/Family_School`  
**Основная ветка:** `main`  
**Первый пилот:** одна семья — Сара (12 лет, 6 класс) и Давид (10 лет, 4 класс)  
**Цель MVP:** семья может вести недельный учебный цикл без таблиц и сторонних сервисов.

---

## 0. Рамки и технические решения

### 0.1. Что строим

HomeEdu — защищённое веб-приложение для семейного обучения. Ребёнок получает план на сегодня, проходит уроки и отправляет работы. Родитель планирует неделю, проверяет результаты и видит прогресс по темам и навыкам.

### 0.2. Что не строим в MVP

- полный контент всех школьных предметов и классов;
- мобильные приложения через App Store / Google Play;
- offline-first синхронизацию;
- публичные рейтинги и социальную сеть;
- автоматическую финальную оценку открытых работ AI;
- отдельный Node/NestJS backend;
- Payload CMS и отдельный контентный портал;
- локальные AI-модели.

### 0.3. Утверждённый стек

| Слой | Решение | Причина |
|---|---|---|
| Frontend | React + TypeScript + Vite | Быстрая разработка и статическая сборка для Beget |
| Маршрутизация | React Router | Кабинеты ребёнка и родителя |
| Стили | Tailwind CSS + shadcn/ui + Radix UI | Быстрые и доступные компоненты с кастомным дизайном |
| Server state | TanStack Query | Кеширование и синхронизация данных с API |
| UI state | Zustand | Выбранный ребёнок, меню, локальные настройки интерфейса |
| Формы | React Hook Form + Zod | Валидация уроков, заданий и проверок |
| API | PHP 8 REST API, `/api/v1` | Совместимо с Beget Free и переносимо на собственный сервер |
| База | MySQL | Одна общая база для устройств семьи |
| Файлы | Приватная директория вне `public_html` | Защита фотографий тетрадей и файлов детей |
| Тесты | Vitest, React Testing Library, Playwright | Проверка логики и критических сценариев |
| AI | Серверный AI Gateway | Ключи не попадают во frontend |

### 0.4. Архитектура

```text
Browser
  └─ React / Vite SPA
       └─ HTTPS → PHP API (/api/v1)
                    ├─ MySQL
                    ├─ Private uploads
                    └─ AI Gateway → выбранный AI-провайдер
```

Frontend ничего не знает о паролях к БД и API-ключах AI. Любая проверка прав доступа выполняется на PHP API. Позже API и MySQL можно перенести на собственный VPS, не меняя публичные API-контракты.

## 1. Правила работы с репозиторием

### 1.1. Структура репозитория

```text
Family_School/
  apps/
    web/                    # React + Vite приложение
    api/                    # PHP REST API
  docs/
    PROJECT_VISION.md
    ROAD_MAP.md
    api-contract.md
    data-model.md
  infra/
    beget/
      deploy.md
      .htaccess.example
  .github/workflows/
  README.md
```

### 1.2. Ветки и коммиты

- `main` всегда содержит рабочее, проверенное состояние;
- для каждой задачи создаётся ветка `codex/<короткое-название>`;
- один pull request — одна логическая цель;
- не коммитить `.env`, пароли, API-ключи, экспорт базы и реальные фото работ;
- формат коммитов: `feat:`, `fix:`, `docs:`, `test:`, `chore:`.

Примеры:

```text
feat: add child pin login
feat: add weekly plan API
fix: restrict submission access by family
docs: add Beget deployment guide
```

### 1.3. Definition of Done для любой задачи

Задача считается завершённой, только если:

- реализован пользовательский сценарий, а не только интерфейс;
- сервер проверяет авторизацию и принадлежность данных семье;
- добавлена валидация входных данных;
- есть тест логики или e2e-тест критического пути;
- нет ключей и персональных данных в репозитории;
- обновлена документация, если изменился API, схема данных или деплой;
- `lint`, `typecheck`, тесты и production build проходят успешно.

## 3. Фаза 2 — База данных, роли и безопасность

**Цель:** создать семейное пространство с защищённым доступом родителя и детей.

### 3.1. Минимальная модель данных

| Таблица | Назначение |
|---|---|
| `families` | семейное пространство |
| `users` | взрослые пользователи и пароль родителя |
| `students` | профили Сары, Давида и будущих детей |
| `parent_student_links` | связь взрослого и ребёнка |
| `student_sessions` | короткоживущие PIN-сессии ребёнка |
| `audit_events` | изменения оценок, настроек и важных данных |

Общие обязательные поля для сущностей: `id` (UUID), `created_at`, `updated_at`. Удаляемые пользователем данные получают `deleted_at`, если требуется восстановление.

### 3.2. Авторизация

- [x] Регистрация первого взрослого при установке.
- [x] Вход родителя: email + пароль.
- [x] Пароль хранится только как современный хеш.
- [x] Создание профиля ребёнка: имя, класс, дата рождения или возрастной диапазон, PIN.
- [x] Вход ребёнка: выбор профиля + PIN.
- [x] Защищённые cookies или токены с ограниченным сроком жизни.
- [x] Middleware/API-guard для родительских и детских маршрутов.
- [x] Rate limit на попытки PIN и входа родителя.
- [x] Выход со всех сессий и смена PIN из кабинета родителя.

### 3.3. Критерии готовности

- родитель не может видеть данные чужой семьи;
- Сара не может открыть данные Давида прямой подстановкой ID в URL;
- ребёнок не может вызвать родительский API;
- ошибочный PIN не раскрывает, существует ли другой профиль;
- изменение PIN и оценки попадает в `audit_events`.

## 4. Фаза 3 — Учебная программа и контент

**Цель:** родитель создаёт и редактирует путь обучения.

### 4.1. Модель программы

```text
Student → Curriculum → Subject → Section → Topic → Lesson → Activity
```

Таблицы:

| Таблица | Назначение |
|---|---|
| `curricula` | программа конкретного ребёнка |
| `subjects` | математика, русский и пользовательские предметы |
| `sections` | крупные разделы предмета |
| `topics` | темы внутри раздела |
| `competencies` | измеряемые навыки темы |
| `competency_prerequisites` | зависимости навыков |
| `lessons` | учебные единицы |
| `content_blocks` | текст, ссылка, видео, изображение, пример |
| `activities` | практика, тест, открытая работа, файл |

### 4.2. Задачи

- [x] CRUD для предметов, разделов, тем и уроков.
- [x] Блочный формат урока: текст, ссылка, видео, изображение, пример, задание.
- [x] Редактор первой версии: простой Markdown/textarea и загрузка ссылок; rich text editor не добавлять до реальной потребности.
- [x] Ручное изменение порядка тем и уроков.
- [x] Возможность добавить пользовательский предмет.
- [ ] Seed-данные: маршрут «Дроби» для 4 и 6 классов.
- [x] Страница родителя «Программа ребёнка».

### 4.3. Первый контентный маршрут

**Давид, 4 класс:** дробь как часть целого → числитель и знаменатель → сравнение простых дробей → простая практика.  
**Сара, 6 класс:** обыкновенные дроби → общий знаменатель → сравнение → сложение и вычитание дробей → практика и проверка.

### 4.4. Критерии готовности

- родитель создаёт предмет, тему, урок и задание без изменения кода;
- урок виден только назначенному ребёнку;
- порядок уроков сохраняется после перезагрузки;
- seed-маршруты доступны для обоих классов.

## 7. Фаза 6 — Прогресс, компетенции и повторение

**Цель:** показывать доказуемое освоение, а не только число открытых уроков.

### 7.1. Модель

| Таблица | Назначение |
|---|---|
| `mastery_states` | текущий статус компетенции у ребёнка |
| `mastery_evidence` | доказательство: тест, практика, объяснение, повторение |
| `review_schedule` | следующее повторение |
| `achievements` | личные достижения |

### 7.2. Правила первой версии

- компетенция начинается в статусе `available`;
- после первой попытки — `learning`;
- после успешной практики и теста — `needs_reinforcement`;
- после успешного повторения спустя заданный интервал — `mastered`;
- при неудачном повторении — снова `needs_reinforcement`;
- если данных недостаточно, статус не повышается автоматически.

Точные пороги выносятся в конфигурацию предмета, а не жёстко кодируются в UI.

- [x] Родитель настраивает для назначенного предмета минимальное число подтверждений, число разных типов успешной работы и интервал первого повторения.

### 7.3. Задачи

- [x] Карта тем ребёнка с понятными статусами.
- [x] Прогресс по предмету и теме.
- [x] Планирование первого повторения после темы.
- [x] Автоматическое задание на повторение с датой, причиной и ссылкой на урок.
- [x] Короткая контрольная повторения из 1–3 вопросов темы с единым результатом.
- [x] Родитель явно выбирает и упорядочивает 1–3 вопроса повторения; до настройки действует автоматический выбор.
- [x] Объяснение рекомендации: какие попытки и результаты её вызвали.
- [x] Достижения за самостоятельную доработку и устойчивое повторение.
- [x] Достижение за самостоятельное объяснение решения, подтверждённое родителем.
- [x] Кабинет родителя «Где требуется помощь».

### 7.4. Критерии готовности

- у каждой рекомендации есть объяснение;
- прогресс не меняется без сохранённого доказательства;
- ребёнок видит личный рост, но не сравнение с другим ребёнком;
- родитель видит разницу между «прошёл урок» и «освоил тему».

## 8. Фаза 7 — AI Gateway

**Цель:** добавить полезный AI без утечки ключей и замены самостоятельной работы.

### 8.1. Принципы

- AI вызывается только сервером;
- ключ провайдера хранится вне Git и вне `public_html`;
- родитель включает AI отдельно для каждого ребёнка;
- в AI-запрос передаются только данные, нужные для конкретной функции;
- ответ AI содержит структуру, уверенность и объяснение;
- решение AI не меняет оценку или программу автоматически.

### 8.2. Порядок реализации

1. [ ] **Подсказка к текущему заданию:** вопрос → минимальная подсказка → похожий пример.
2. [ ] **Генерация черновика теста:** родитель проверяет и сохраняет вопросы.
3. [ ] **Рекомендация по слабой теме:** анализирует историю и предлагает практику.
4. [ ] **Черновик проверки открытой работы:** возвращает замечания по рубрике и уверенность; родитель утверждает итог.
5. [ ] **Черновик недельного плана:** родитель принимает или редактирует.

### 8.3. Запреты

- не раскрывать готовое решение до попытки ребёнка, если не разрешил родитель;
- не давать окончательную оценку открытой работе;
- не делать психологические или медицинские выводы;
- не отправлять фото работ внешнему AI без отдельного согласия родителя;
- не использовать свободный неструктурированный AI-ответ как источник оценок.

### 8.4. Критерии готовности

- ни один AI-ключ не отображается в DevTools или в Git;
- родитель может отключить AI;
- подсказка не содержит готовый ответ до разрешённой стадии;
- AI-результат сохраняет модель, версию промпта, дату и уровень уверенности.

## 10. Фаза 9 — Деплой на Beget

- [ ] Настроить CORS только для собственного домена или не использовать CORS при одном домене.

### 10.2. Процесс деплоя

```text
1. Запустить lint, typecheck, tests и production build локально/в CI.
2. Сделать резервную копию production MySQL.
3. Применить миграции БД.
4. Загрузить содержимое apps/web/dist в public_html.
5. Загрузить PHP API и приватные конфигурации.
6. Проверить /api/v1/health.
7. Пройти smoke test: вход родителя → вход ребёнка → урок → отправка → проверка.
8. Зафиксировать версию релиза и выполнить rollback-план при ошибке.
```

### 10.3. Ограничения Beget Free

- не использовать фоновые демоны, очереди и тяжёлые задачи;
- не запускать локальную AI-модель;
- не хранить большие видеофайлы;
- контролировать объём загруженных фото;
- при росте нагрузки, количества семей или AI-вызовов переносить API и БД на собственный VPS.

### 10.4. Критерии готовности

- сайт открывается только по HTTPS;
- API не показывает stack trace и секреты;
- загрузки не доступны напрямую;
- восстановление резервной копии проверено;
- пользовательский сценарий проходит на production-домене.

## 11. Фаза 10 — Расширение после MVP

Начинать только после того, как Сара и Давид регулярно используют MVP минимум месяц.

Приоритеты:

1. дополнительные предметы и готовые шаблоны уроков;
2. богатый редактор контента или Payload CMS при появлении регулярной редакторской работы;
3. PWA-кеширование материалов и ограниченный офлайн-режим;
4. добровольная синхронизация или миграция на собственный сервер;
5. голосовые ответы;
6. проектные и межпредметные маршруты;
7. роли наставника и репетитора;
8. мобильная упаковка через Capacitor при доказанной необходимости.

## 12. Контрольные точки продукта

| Контрольная точка | Вопрос |
|---|---|
| После фазы 3 | Родитель может сам создать и назначить урок? |
| После фазы 5 | Ребёнок может выполнить и отправить работу без стороннего сервиса? |
| После фазы 6 | Видно, что ребёнок освоил, а не просто открыл урок? |
| После фазы 7 | AI помогает думать, а не отвечает вместо ребёнка? |
| После фазы 9 | Семья может вести неделю обучения без таблиц и без риска потери данных? |

## 13. Критерий успеха MVP

MVP успешен, если за четыре недели:

- Сара и Давид занимаются в HomeEdu не менее четырёх дней в неделю;
- не менее 80% заданий недельного плана завершаются;
- родитель планирует следующую неделю не более 30 минут;
- родитель понимает прогресс каждого ребёнка менее чем за пять минут;
- хотя бы одна слабая тема каждого ребёнка выявлена, проработана и подтверждена повторением;
- ни одна критическая учебная запись не потеряна;
- семья может отказаться от внешних таблиц для базового планирования и учёта.
