# HomeEdu — модель данных фазы 2

```text
families
 ├── users (родители)
 ├── students (дети)
 ├── sessions
 └── audit_events

users ──< parent_student_links >── students
```

## Инварианты

- каждая бизнес-сущность принадлежит одной семье;
- сервер определяет `family_id` из сессии, а не доверяет значению клиента;
- родитель может работать только со связанными профилями своей семьи;
- детская сессия связана ровно с одним профилем;
- смена PIN завершает все активные сессии ребёнка;
- сырые session token, пароль и PIN никогда не хранятся в базе;
- важные изменения записываются в `audit_events`.

Полная схема создаётся миграцией `apps/api/migrations/001_initial.sql`.
